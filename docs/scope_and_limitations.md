# v1.0 适用范围与扩展路线

## 一、v1.0 定位

本 Demo 聚焦 **"知识工作者个体成长赋能"**——即以**数字化工作行为流**为信号、以**个体能力成长**为目标的场景。

### ✅ 覆盖岗位（v1.0 支持）

| 岗位方向 | 行为信号 | 能力本体分支 | 样例员工 |
| --- | --- | --- | --- |
| 后端研发 | TAPD 任务 / Git commit / PR / 线上 Ticket | 硬技能（编程/数据库/分布式）+ 工具 | emp_001, emp_006, emp_013 |
| 前端研发 | Git commit / PR / 组件产出 / 线上问题 | 硬技能（TS/UX）+ 工具 | emp_002, emp_008, emp_016 |
| 算法 / AI 应用 | Notebook / 实验记录 / 模型版本 / 上线指标 | 硬技能（ML/DL）+ Prompt 工具 | emp_003, emp_009, emp_015 |
| 数据工程 / 分析 | SQL / Notebook / 数仓产出 / BI 报表 | 硬技能（数据）+ 工具 | emp_004, emp_012, emp_017 |
| 产品经理 / 设计 | PRD / 评审记录 / 原型 / 数据洞察 | 硬技能（产品/UX）+ 软技能 | emp_005, emp_011, emp_014 |
| 测试 / 安全 / 运维 | 测试脚本 / 故障复盘 / 安全事件 / 监控大盘 | 硬技能（测试/安全）+ 工具 | emp_007, emp_010, emp_019 |
| 技术主管 | 上述任意 + 评审 / OKR / 1:1 纪要 | 软技能主导 + 硬技能储备 | emp_018 |

### ❌ 不覆盖（v1.0 边界，列入 Phase 4）

| 岗位 / 场景 | 为什么 v1.0 不覆盖 |
| --- | --- |
| **销售 / 客户成功** | 行为流在 CRM（通话 / 拜访 / 合同），数字化颗粒度低；能力更依赖谈判 / 情商 / 关系维护等软技能 |
| **HR / 招聘** | 行为流大量发生在面试、谈话、线下；关键能力（识人、判断）难以从文本事件抽取 |
| **客服 / 人工审核** | 对话质检更适合用专用 NLP Pipeline，而不是通用能力本体 |
| **法务 / 财务 / 合规** | 产出是判断与文本质量，不是"建构式"的工件；能力评估要靠更高成本的人工 |
| **后勤 / 行政 / 司机** | 行为非数字化 |
| **团队 / 组织级赋能** | Demo 只建模了个体，没有 Team / OrgUnit 数据模型 |
| **心理健康 / 职业倦怠识别** | 涉及隐私与伦理高风险，超出本 Demo 范畴 |

### ⚠️ 失灵场景（即便在 ✅ 范围内也要谨慎）

- **员工任期 < 3 个月**：行为流样本太少，Bayesian 后验尚未稳定；UI 应降级到"静态画像模式"
- **员工跨领域转岗**：能力衰减模型会误判（老领域衰减 vs 新领域积累），需要手动打"转岗标记"
- **长期休假归来**：时间衰减会夸大能力损失（实际上工作记忆是渐进恢复的），需要"回归缓冲期"

## 二、Phase 4 扩展路线矩阵

| 扩展方向 | 关键改造 | 数据需求 | 难度 | 交付目标 |
| --- | --- | --- | --- | --- |
| **A. 多岗位适配** | 为每类岗位定义差异化行为流配方 + 能力本体扩展（非技术分支） | 新岗位的结构化行为流（销售 CRM / HR 访谈 / 客服对话质检） | 中 | 3-5 个新岗位可用 |
| **B. 组织级赋能** | 新增 `Team` / `OrgUnit` 数据模型；配对推荐（peer mentoring matrix）；团队能力热力图；继任者地图 | 组织架构表 + 团队任务归属 | 中 | 管理者 / HRBP 视图 |
| **C. 软技能归因精细化** | 自评 + 360 反馈 + 情境模拟题三角验证；用对话语料做 STAR 结构抽取；新增"模拟练习"赋能形态 | 反馈问卷数据 + 会议 / 评审纪要 | 高 | 软技能 F1 提升到 0.7+ |
| **D. 生产化** | 真实 TAPD / Git / OA API 接入 + 权限审计 + 持续反馈闭环 + A/B 实验平台 | 企业 HRIS / DevOps 接口 + 法务授权 | 高（合规为主） | MAU 千人级可用 |

### A. 多岗位适配的具体做法（以销售岗为例）

```yaml
岗位包: "销售经理"
能力本体扩展:
  - C.sales.prospecting      # 潜客挖掘
  - C.sales.negotiation      # 谈判
  - C.sales.account_mgmt     # 大客户运营
  - C.sales.forecast         # 销售预测
行为流配方:
  - source: "crm_activity"   # 通话次数 / 拜访次数
  - source: "deal_update"    # 赢单 / 失单 / 推进节点
  - source: "contract"       # 合同额 / 毛利
事件归因差异:
  - 学习资源以"话术 playbook + 优秀销售的成交录音"为主（不是课程）
  - experiential 分组主打"跟单观摩 + 分配小单实战"
```

相当于给每个岗位包 ship 一份：
- 能力本体 patch
- 行为流 schema
- 资源池扩展
- 触发规则调整

### B. 组织级赋能

核心新增：**Team-level Profile**
```python
class TeamProfile(BaseModel):
    team_id: str
    members: list[str]                       # employee_id 列表
    aggregated_competencies: dict[str, float]  # 平均 level
    competency_coverage: dict[str, int]      # L4+ 人数
    critical_gaps: list[GapItem]             # 团队级薄弱项
    mentoring_matrix: list[tuple[str, str, list[str]]]  # (mentor, mentee, competencies)
```

应用场景：
- 技术主管查看团队能力热力图
- HRBP 识别关键能力断层，规划招聘
- 配对推荐：基于 Expert Finder 找到可互补的"导师-学员"对

### C. 软技能归因

当前 v1.0 的软技能评估依靠自评 + 项目描述，准确率是软肋。Phase 4 的三角验证：

1. **自评问卷**（员工侧）：结构化题目 → score
2. **360 反馈**（同侪 / 上级 / 下属 / 跨团队各 2 人）：匿名评分 + 评语
3. **情境模拟题**（系统侧）：给出 3-5 个决策情境，员工选择，根据选择模式打标

叠加"模拟练习"赋能形态：情境题 / 角色扮演 / 决策沙盘。

### D. 生产化的合规护栏

- **数据采集**：员工明示同意 + 可随时关闭/导出/删除（DPIA 文档化）
- **权限审计**：谁看了谁的画像，全部可溯源；本人 always 可见
- **算法透明**：每条推荐都提供"为什么推给我"的解释
- **反馈闭环**：员工可标记"推荐不相关"，反哺模型精排

## 三、在 v1.0 中如何显式声明边界？

- 首页 Hero 下方已加 v1.0 边界说明
- README 顶部卡片
- 每份 JD 配一个 `v1_applicable: bool` 字段（未启用，Phase 4 引入）
- Streamlit 推荐页可引入"信心条"（confidence bar）——当员工能力证据不足时降级提示

## 四、总结

> v1.0 做的事：**把能在行为流里看得见的知识工作者成长路径清晰化、结构化、并按 70-20-10 组织推送**。
>
> v1.0 不做的事：**替代人的判断**、**处理隐私敏感场景**、**推广到行为非数字化岗位**、**提供管理者级团队视图**。

明确边界，反而让这个 Demo 的价值更可信。
