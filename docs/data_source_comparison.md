# 数据源方案对比

## 一、二选一矩阵

| 维度 | 方案 A：公开 + 模拟数据（Demo 默认） | 方案 B：企业内部真实数据（生产化） |
| --- | --- | --- |
| 能力框架 | O\*NET / ESCO / LinkedIn Skills | 企业胜任力模型（如腾讯 TMP） |
| 员工基础资料 | 公开 LinkedIn 简历 / LLM 生成 | HRIS（组织架构 / 职级 / 入职日期） |
| 岗位 JD | 猎聘 / Boss / LinkedIn | 企业岗位说明书 |
| 行为事件流 | LLM 批量生成 | TAPD / Git / Confluence / 企业微信 / OKR API |
| 绩效反馈 | 模拟生成 | OKR / 360 / 绩效系统 |
| 学习资源 | 公开课元数据（Coursera / B站 / 极客时间） | 企业自有资源池（腾讯乐享 / 学堂在线） |
| 合规与隐私 | 无 PII，零合规成本 | **需要 DPIA + 员工同意 + 脱敏链路 + 审计** |
| 数据质量 | 可控、可重复 | 真实但嘈杂 |
| 个性化效果 | 中（偏类型化） | 高（真实行为） |
| 启动成本 | 低（1 周能跑通） | 高（数月：法务 + 接口 + 脱敏） |
| 维护成本 | 低 | 高（接口变更、数据质量巡检） |

## 二、本 Demo 的选择：方案 A

选择方案 A 的三个关键原因：

1. **零合规门槛**：Demo 要能快速迭代给不同受众看，没时间走法务流程
2. **可控可重复**：每次演示的员工画像、推荐结果一致，便于讲解
3. **先把"形"立起来**：重点是证明"能力本体 + 动态画像 + 70-20-10 推荐"这套方法是成立的，数据真实度只要"到业务人员认得出"即可

## 三、Demo 数据的真实度控制

我们用三层保证让"模拟数据"听起来像真的：

### 3.1 员工画像来自行业观察

20 位员工的 `current_role`、项目经历、`base_competencies`、自评都参考了真实职场中的岗位画像分布：
- 新人（0-1y）：emp_008, emp_013
- 中坚（2-4y）：emp_001~005, emp_007, emp_009, emp_012, emp_015, emp_016, emp_017, emp_019, emp_020
- 资深 / Lead（5y+）：emp_006, emp_010, emp_011, emp_014, emp_018

覆盖 9 个岗位方向（后端/前端/算法/数据工程/数据分析/产品/设计/测试/运维/安全/iOS）。

### 3.2 资源池来自公开数据

10 类 155 条资源全部来自真实可查的公开内容：
- 极客时间 / 拉勾 / 得到 / B站 / 慕课网的实际课程
- deeplearning.ai / Coursera 的真实英文课
- 《DDIA》《架构整洁之道》《金字塔原理》等真实书籍
- GitHub Copilot / Cursor / LangChain / Airflow 等真实工具

### 3.3 行为流通过模板 + 能力采样生成

6 个月共 9400 条事件，每条带 `competency_hints` 作为 ground truth。生成器逻辑：
- 按员工 base_competencies 加权采样主能力
- 按 source 类型选对应文案模板
- 工作日 2-5 条 / 周末 0-1 条的节奏
- 评审打回、绩效肯定等负向/正向事件都有

生成的事件文本不会有具体项目代号、同事姓名、业务数字，**保证脱敏**。

## 四、生产化迁移路径

当方案 A 走通、形态被业务认可后，逐步向方案 B 迁移：

### 阶段 1：接入 Git 与 TAPD（约 1 个月）
- 最少合规成本的第一步（代码 + 任务管理都相对公开）
- 取代模拟的 code 和 task 事件流
- 画像准确率能上升一个台阶

### 阶段 2：接入 Confluence + OKR（约 2 个月，需审批）
- 取代 doc + feedback 事件流
- feedback 是权重最大的事件源，对画像影响显著

### 阶段 3：接入 IM / 会议（约 3 个月，敏感度高）
- 用 LLM 先做摘要再入库，不存原文
- 取代 meeting 事件

### 阶段 4：完全切换（6 个月+）
- 下线 LLM 生成器
- 上线完整监控与反馈闭环

## 五、混合模式（推荐实际落地）

不用等到阶段 4 才用"真数据 + 公开资源池"。更现实的混合：

| 层 | 来源 | 优先级 |
| --- | --- | --- |
| 员工 / 行为事件 | 企业内部 | 高（核心价值） |
| 能力本体 | 公开 O\*NET + 企业自定义 patch | 公开为主 |
| 学习资源 | **公开 + 企业内部双轨** | 都要，按员工偏好加权 |
| 岗位 JD | 企业内部 | 高（HR 权威） |
| Mentor 池 | 企业内部 | 高 |

**核心判断**：资源池越"全"越好（不限于企业内部），员工越"真"越好（要用真数据），岗位越"准"越好（用 HR 内部 JD）。
